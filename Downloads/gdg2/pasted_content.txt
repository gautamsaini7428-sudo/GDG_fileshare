8. ACCESS CONTROL / SECURITY
==================================================

This is extremely important.

A user must NEVER be able to access another user's files.

Every file must belong to the authenticated user's user ID.

Database structure should include something similar to:

users
files

files:
- id
- user_id
- file_name
- file_type
- file_size
- storage_path
- uploaded_at

Every database query must verify the authenticated user's ID.

Implement proper backend authorization/security rules.

For Supabase:
Use Row Level Security (RLS).

Users should only be able to:
- Read their own files
- Upload their own files
- Download their own files
- Delete their own files

They must NOT be able to:
- Read another user's file metadata
- Download another user's file
- Delete another user's file
- Modify another user's file

Do not rely only on frontend checks.
Enforce access control at the backend/database/storage level.

==================================================
9. DECISIONS.md
==================================================

Create a file:

DECISIONS.md

Document at least one important access-control decision.

Example:

# Access Control Decision

Each uploaded file is associated with the authenticated user's unique user_id.

Database Row Level Security ensures that users can only SELECT, INSERT and DELETE rows where user_id matches the currently authenticated user.

Storage access is also restricted to the user's own storage path.

This prevents one authenticated user from accessing another user's files even if they manually modify a request URL.
